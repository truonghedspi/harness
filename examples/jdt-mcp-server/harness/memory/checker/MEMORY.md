# Checker memory — JDT MCP Server

Index of what the checker agent has learned across runs (`harness/docs/reference/agent-memory.md` documents the schema and why). One line per entry, always loaded — keep it
short; the reasoning lives in the linked file, read that only when the line looks relevant.

Write a new entry when a maker's claim looked right but wasn't (and how you actually caught it),
or a class of feature keeps needing the same scrutiny. Don't write one for a routine approve/reject
— that's the job working as intended, not a lesson.

Write entries and hooks **in English**, whatever language the rest of the project uses: memory is
addressed to whichever agent reads it next, not to this project's readers. Entries already written
in another language stay as they are — this governs what gets written from now on.

- [Baseline gate oracle seam](baseline-gate-oracle-seam.md) — Helper-only tests do not prove that the startup gate calls the helper or propagates its failures.

- [Accepted risk validated by nothing](accepted-risk-validated-by-nothing.md) — "Validated only against the current fixture tree" can mean validated by no condition at all.
- [Sibling pre-authored oracle goes unrun](sibling-preauthored-oracle-goes-unrun.md) — When a build feature creates a module for the first time, run every pre-authored oracle that targets it; the feature's own verification command never does, and a red there is often an oracle defect, not an implementation defect.
- [Redundant fallback masks a mutant](redundant-fallback-masks-a-mutant.md) — Deleting SIGTERM proves nothing while the SIGKILL escalation still reaps the child; count the mechanisms in the function before designing the mutant.
- [Superlative in invariant needs two candidates](superlative-in-invariant-needs-two-candidates.md) — A word like outermost/nearest is verified by nothing unless a fixture offers two candidates on that axis; the qualifier clause after it (`that declares X`) is a third axis, and closing one axis per round trickles gaps forever.
- [Flake fixed inside the oracle hides a production defect](flake-fixed-inside-the-oracle-hides-a-production-defect.md) — A test-side workaround (probe file, warm-up loop) with no production counterpart means the flake was an implementation gap, not a test artifact; check `docs/assumptions.md` for the row the measurement already falsifies. Same entry: when the implementation decides on a tuple like `(mtime, size, ino)`, demand one case per field in a single round — closing one field per round trickles gaps forever.
- [Maker-authored mutants cover only branches he wrote](maker-authored-mutants-cover-only-branches-he-wrote.md) — On a build feature where the maker writes his own oracle, every mutant he reports can reproduce and the oracle still be blind; build yours from three axes he cannot see — protocol constants the test re-imports from the module under test, the mechanism his own rationale calls load-bearing, and the single fixture shape every case shares.
- [A test timeout does not cover the after hook](test-timeout-does-not-cover-the-after-hook.md) — `{ timeout: N }` bounds the test body only; an unbounded `await` in `t.after` (server.close, child.kill) hangs forever with no failure line, so aim one mutant at the cleanup path and watch the wall clock.
- [Green suite that never terminates](green-suite-that-never-terminates.md) — Bounding every `await` in cleanup catches shutdown that never settles, not shutdown that settles early and leaks a listening handle; flip the `if (!server.listening)` early-out and watch for `ok 1..N` followed by silence, and always run mutants of this class through a process-group-killing timeout wrapper.
- [Surviving mutant claimed equivalent](surviving-mutant-claimed-equivalent.md) — A mutant that survives on defensive code may genuinely be equivalent; accept it only after you rebuild it, read the synchronous window for a missing `await`, and run your own probe — then demand the comment be demoted from "this guarantees INV-X" to unproven redundancy.
- [Returned teardown function is an untested API surface](returned-teardown-function-is-an-untested-api-surface.md) — A method returning `() => void` (unsubscribe/detach/close) is a second API surface no case touches; `return () => {};` survives, and it hides a paired mutant because the only case that discriminates the dispatch-loop snapshot must call that returned function.
- [Mỏ neo dương bạn yêu cầu cũng phải được đo bằng mutant](anchor-you-demanded-must-itself-be-mutated.md) — Lượt trước bạn đòi thêm một khẳng định chống-xanh-rỗng-nghĩa, lượt sau maker thêm đúng câu đó; đọc thấy nó là kiểm tra sự hiện diện, không phải tác dụng. Nợ đúng một mutant phá cơ chế mà mỏ neo khẳng định, rồi đòi ca fail ĐÚNG tại dòng mỏ neo với đúng thông báo của nó.
- [Nguyên tắc oracle maker tự phát biểu thường chỉ áp hai phần ba](mot-nguyen-tac-ap-hai-phan-ba.md) — Khi maker giải thích vì sao một lớp ca phải đắt hơn, đếm số vị trí gọi cơ chế được bảo vệ rồi đối chiếu với danh sách ca chạy ở mức đắt; phần chênh là mutant cần dựng. Cùng entry: khi một chú thích khẳng định tính bất biến, đếm số cơ chế cùng thực thi câu đó — hai cơ chế ở hai hàm khác nhau đỡ cho nhau khiến mọi mutant đơn lẻ sống sót, chỉ mutant phá cả cụm mới lộ ra oracle mù.
- [Chú thích của ca kiểm thử khẳng định fixture chứa trường hợp biên — hãy tính lại số học](fixture-comment-claims-a-boundary-it-does-not-contain.md) — "một ký tự non-ASCII vắt qua ranh giới chunk" hoá ra không có thật: tiền tố 42 byte cộng bước 30.000 byte làm mọi ranh giới rơi đúng đầu ký tự, nên mutant bỏ `StringDecoder` sống sót. Cùng entry: trước khi kết luận một mutant là tương đương, đo tính tới được của nhánh bằng probe ghi tệp; và đo luôn cách dựng ca mới trước khi đòi (`resetAndDestroy()` ném lỗi trên Unix socket, `EPIPE` mới là đường đi được).
- [Mutant chết chứng minh nhánh có ích, không chứng minh lý do trong chú thích](mutant-chet-khong-chung-minh-ly-do-trong-chu-thich.md) — Ca đỏ vì hết giờ chờ một dòng log và ca đỏ vì tiến trình sập cho cùng một màu; đọc thông báo lỗi chứ đừng đọc màu. Mọi helper gói `connect()` vào promise bằng `once("connect")` + `once("error")` đều để sót một listener đã settled trên socket trả về, biến "sập ngay" thành "nuốt im lặng" đúng một sự kiện — đếm `listenerCount("error")` trước khi tin ngữ nghĩa mặc định của Node.
- [Sandbox mutant nằm trong repo bị chính test runner phát hiện](sandbox-mutant-bi-runner-phat-hien.md) — `node --test` không tham số quét đệ quy cả cây, nên các thư mục mutant trong `harness/trace/scratch/` bị chạy chung và làm suite đỏ giả (1722 ca, 99 đỏ, gồm cả ca đang phê duyệt); đếm số ca và tìm tên ca lặp lại trước khi tin, và xoá sandbox trước mọi lượt chạy toàn bộ suite.
- [Teardown chạy trước khi startup kịp đăng ký](teardown-chay-truoc-khi-startup-kip-dang-ky.md) — Mọi mutant về evict đều chạy trên fixture đã start xong, nên trục thời gian không ai chạm: dựng probe có spawn seam chậm, gọi acquire() không await rồi close(), đếm attached với detached (ở đây 1 và 0, tiến trình không thoát). Cùng entry: một toạ độ nấp trong template string của thông điệp lỗi là ranh giới chuyển đổi thứ hai — grep tên hằng số thay vì tin chú thích "chỉ hai hàm".

Hỏi "so với bản nào" trước tiên, rồi tìm bản pristine của lượt trước trong scratchpad dùng chung của phiên và chạy `diff -u` đầy đủ — `git diff` vô dụng khi tính năng trước chưa commit.
- ["Cùng đường dẫn tương đối" không phải "cùng khoá cache"](cung-duong-dan-tuong-doi-khong-phai-cung-khoa-cache.md) — Liệt kê từng thành phần của khoá thật trong mã rồi hỏi fixture có giữ thành phần nào BẰNG NHAU giữa hai phía; thành phần vốn đã khác nhau thì mutant xoá nó khỏi khoá sẽ sống sót, dù cụm từ mô tả kịch bản nghe rất giống một ca cách ly. Cùng entry: trước khi gọi mutant là tương đương, chạy oracle unit sẵn có của component đó trên chính mutant.
